# 本地笔记与知识库（qmd）

本机没有这个源时（`command -v qmd` 无输出，或知识库没索引到相关目录）：**不要报「查无此项」**，
在 `Sources Consulted` 里写成 `not available in this environment`，并说清缺什么。

## 这个源里有什么

个人的 markdown 笔记、知识库、wiki 摘要：设计方案、读过的文章、会议记录、排查笔记、复盘。
这些往往**写于代码之前**，是设计动机最原始的一手材料。

它和 Confluence 的区别：Confluence 是团队的长文档，这里是个人的工作笔记，未成文的推理更多。

## 怎么搜

`qmd` 有 CLI，调查者（子会话）可以直接用 `bash` 跑：

```bash
qmd query "<自然语言问题>"                 # 混合检索 + 扩展 + 重排（推荐起手）
qmd search "<关键词>"                      # BM25 全文，快，不需要 LLM
qmd get <path>[:from[:count]]              # 取文档全文（带行号）
qmd multi-get "<glob>"                     # 批量取
```

起手用 `query`，拿到候选路径后用 `get` 读全文。关键词明确时用 `search` 更省。

检索词从这些里取：

- 功能名、关键符号 / 类名
- PR 作者的名字（笔记常早于代码）
- 错误字符串、用户可见的词
- 时间：知道代码什么时候上的，就按那个时段找

## 好证据长什么样

- 一篇写于代码之前的方案笔记，有「问题」「为什么选这个」这类小节
- 「考虑过的其他做法」或「否掉的方案」小节
- 一次排查笔记，把目标代码记成某次故障的处置手段
- 会议记录里写了「我们决定 X，因为 Y」，且作者与时段对得上 PR

## 常见坑

- **笔记过期。** 方案常写在实现之前且之后没更新。它可能描述了一个后来改掉的计划。对着实际 PR 核。
- **笔记与代码漂移。** 笔记说「我们会做 X」，代码实际做 Y。把这个分歧标出来，综合者会摆它。
- **只有标题相关。** 检索命中的是同一领域的别的主题，不是这段代码。读全文再判。
- **索引不全。** 索引只覆盖配置过的目录。目标笔记不在索引里时，这是**缺口**，不是空结果。
- **检索词太窄。** 同一个概念在笔记里常用不同说法。换两三种表述再试。

## 要返回什么

每份相关文档：

- 路径（与标题）
- 作者与最后更新日期（能拿到就给）
- 动机原文（逐字引文）及其位置
- 相关链接
- 它是成稿还是草稿
