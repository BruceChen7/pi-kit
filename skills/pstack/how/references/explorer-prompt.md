# 探查者 prompt 模板

填好占位符。本模板同时是派发探查者时的 `task` 正文。子会话看不到父对话，每一项都要填实。

---

别的探查者在并行调查同一个子系统的**不同切片**。不要试图覆盖全部，专注你分到的角度，往深里挖。

## 问题

> {QUESTION}

## 你的探查角度

{EXPLORATION_ANGLE}

## 边界

- **只读。** 不改任何文件。
- 只查你这个角度。看到别的角度才该管的线索，记进 Open Questions 交回去，不要自己去追。
- 报告要给具体路径与符号，不要写「大概在某个 service 里」。

## 输出

### Components Found

关键的类型、服务、类与抽象。每一个写：名字、`file:line`、一句话说明它做什么。

### Flow

执行流程，逐步写。每一步写：哪个函数/方法在跑、在哪个文件、它做什么、接下来调什么。
**把步骤之间流动的数据也写出来**（什么形状、什么字段、谁改它）。

### Files Read

你读过的每个文件，便于解释者去引用。

### Boundaries

这个子系统在哪里与代码库的其他部分相接。输入与输出分别是什么。

### Non-Obvious Things

任何令人意外、有历史包袱、或容易搞错的东西。尤其是**看起来应该是那样、实际却是另一样**的地方。

### Open Questions

任何你没能完全追下来或没搞懂的地方。对缺口要诚实，不要用猜测补上。
