# Figure it out

任务匹配不上任何现有 route 时，**设计一条 route**。

动任何代码之前，交付物是**流程本身**：一串阶段，按任务风险缩放严谨度，跑科学方法，留下一条人离开后回来能审计的决策轨。

默认中文交付。`file:line`、命令、产物路径原样保留。

## A. 定框

**先落地，再承诺。** 在能说出下面三件事之前不要起跑：

1. **完成判据**，写成可证伪的谓词（`prove-it-works`）。测试全绿、复现修好、N 个 PR 全合、
   像素差为零。
2. **范围**，量化：大致规模与工作量，以及落地阶段找出来的阻塞项。
3. **严谨度**，**偏高取**。单向门与高影响面的多给，可逆低风险步骤少给。
   严谨度是**闸门与产物**，不是「再仔细一点」。

定完框，把取舍摆出来再承诺长跑。可逆的活直接开（`never-block-on-the-human`），
但多小时的跑换一次确认点。

## B. 设计流程

拆成原子、可独立落地的小单元。**风险最大的未知排最前。** 脚手架与验证在功能之前
（`foundational-thinking`）。

- **先建验证 harness**，并在动手前抓下改动前的基线，让检查读起来是「旧值 vs 新值」。
- 涉及单向门的设计决定，走 `/skill:codebase-design` 做并行方案探索，用
  `DESIGN-RED-FLAGS.md` 逐条筛候选。**形状已经明确的机械活跳过它**；对一个已定的设计再跑一轮
  候选探索是过度工程（`laziness-protocol`）。
- 决定哪些活扇出。**只在接缝处并行**，每个 worker 有自己的输出目录或 patch；
  同一工作树不并发写（`separate-before-serializing-shared-state`）。
- **把设计出来的阶段清单写下来。** 那份清单就是给人复核的东西。

然后执行这份设计。把它的步骤作为具体待办插进 todo 列表，按 C 阶段的循环纪律逐条跑，
把 D 阶段的日志织进去：**每落地一步写一行，不要攒到最后一次性补。**

## C. 跑循环

每个单元是一次实验。

1. **先写假设。**
2. **做最小的改动。**
3. **对着真实产物测**那个谓词。
4. **推进了就留下，没推进就回滚。**

按 `sequence-verifiable-units` 每单元验证完再进下一个，不要攒到最后一起验。

- **看产物，不看自述。** 东西过得太轻松时，先怀疑观察方法，再怀疑系统。
- **委派出去的活配一个裁判。** worker 钻了空子就重置并把契约写严；闸门本身错了就把闸门
  单独改一次，不要绕过去。
- 判定只有三种：**VERIFIED / NOT VERIFIED / INCONCLUSIVE**。**Inconclusive 不算通过。**
  不要藏掉负结果。

## D. 留决策轨

用 `/skill:show-me-your-work` 记录这次跑。

`figure-it-out` 的活通常够雄心，**把决策轨提交上去**，让 reviewer 能在 PR 里读它。
决策轨加 diff，是人离开一段时间回来后能信任这次工作的依据。

## E. 验证并交接

对着 A 阶段那个谓词，在**真实产品**上验整体，不只在 harness 上验。

反复出现的纠正要固化成闸门、lint、检查或脚本（`encode-lessons-in-structure`）。

**回复：** 你设计出来的流程、严谨度与理由、决策轨路径、对着谓词验了什么、还开着什么。

## 边界

- 不匹配 route 时，不要现编一份「像是流程」的清单就开跑；**流程本身就是先交付的产物**。
- 严谨度不可下调来迁就进度；谓词不因难而放宽。
- 不走云隔离、不走同一工作树并发写。
- 交付诊断不交付修法的场景走别的路：活进程症状走 `/skill:poteto-playbooks` 的
  `runtime-forensics`，已有 profile 走 `trace-forensics`。
- 只设计并执行这次跑的流程，不改别的 skill 的正文。
