# Recall

**开工或续接之前，先把用户最近的工作上下文重建出来，交一份紧凑的胶囊：现在到哪了、下一步做什么。**

保持紧凑、贴着主题。只读本次范围内那几条线所需的东西，然后停。

## 上下文活在两份记录里

- **你自己的会话史**：你做过什么、决定过什么。
- **共享记录**：同一段代码在别的名义下发生的一切——用户反复报的症状、上线了又被回滚的修复、
  线上还在响的错误。

一个 bug 尾巴很长的功能，故事大部分在第二份记录里。**不要只从自己的会话记录重建它。**

第二份记录正是 `/skill:why` 在查的东西（源码史、工单、长文档、可观测、错误追踪、数仓）。
本 skill 复用它的来源调查者与逐来源方法。

### Pi 的会话记录在哪

```bash
# slug 是当前工作目录去掉开头的 /、把 / 换成 -、两头各加 --
slug="--$(pwd | sed 's|^/||; s|/|-|g')--"
ls -t ~/.pi/agent/sessions/"$slug"/*.jsonl | head -10
```

一行一个事件。**只读本工作区的目录。** 不要把 `~/.pi/agent/sessions/*` 整个 glob 一遍，
那会读到无关的私人会话。

## 步骤

1. **先分类，再路由。** 要续接**某一个具体会话**是交接文档（`/skill:handoff`），不是这个。
   把习惯做成持久的 skill 是另一件事。人要读的工作总结又是另一件。**本 skill 是在动手之前
   载入跨若干会话的工作上下文。** 用户已经给了一份状态胶囊（路径、分支、改动）时，直接用，
   跳过挖掘。
2. **先锁范围。** 定窗口（「最近」是个真实区间，默认最近 7 天）、主题（点了名就用它）、
   工作区（默认当前这个，**未经要求绝不读别的项目的会话**）。把范围复述回去。
   **绝不悄悄把「全部」当成「最近 N 条」。**
3. **在会话史里并行挖。** 派若干个只读子会话（`subagent`，`agent: "explore"`，`background: true`），
   每个分一片语料，一次 `subagent action: "wait"` 收。要求每个子会话：
   - 按真实修改时间排序（`ls -t`），**绝不按文件名里的 UUID 排序**；
   - 先用 `grep` 命中主题，再只读匹配上的会话，且只读其中相关的区段；
   - 跳过当前这次会话，以及明显的噪音（子会话、eval、测试会话）。

   每个子会话返回同一套结构，一个会话一块：主题、用户的目标、决定、未结的线、
   卡住的地方与纠正、产物（PR、工单、分支），**每条都引用会话文件名**。

   只有一两个会话时跳过 fan-out，直接搜。**原始记录留在子会话里**，主线程只收它们的发现。
4. **有具名目标时扫共享记录。** 主题点了功能、文件、子系统、领域或 bug 时，这是**默认动作，不是
   判断题**，「我在 X 上的工作」不构成豁免。把它交给 `/skill:why` 的来源调查者，但把问题从
   「当初为什么这么建」扭成「**现在的状态是什么、试过什么没成、用户还在报什么**」。
   复用它的逐来源方法，与第 3 步并行跑，继承它的姿态：一个源一个调查者、空结果也是发现、
   本机没有的源照实说。把结果折进简报。

   **只有纯粹的活跃度回顾**（「我这周干了什么」，没有具名目标）才跳过这一步，那时你自己的记录
   与当前状态就是全部答案。
5. **对着当前实际状态核对。** 挖出来的 PR、分支、工单，用 `git` 和 `gh` / `glab`
   （按 `git remote -v` 选）核一遍。答案取决于某个 agent **实际做了什么**（跑了哪些工具、读了
   哪些文件、撞了什么错）时，读完整记录，不要只信摘要。
6. **按下面的契约写简报。** 按线组织。贴着点名的主题。

## 输出契约

顺序是：胶囊 → 各条线的状态 → 问题 → 下一步。更细的内容往下放或被砍掉。

- **Capsule**：最多 5 条。这件事是什么、整体到哪了。
- **Threads**：一条线一行，**行首恰好一个状态标签**：
  `[merged #N]`、`[open PR #N]`、`[in flight <branch>]`、`[verified, uncommitted]`、
  `[reverted #N]`、`[planned, not started]`。
  **没有标签的线就是还没完，给它打上标签。**
- **Problems**：最多 5 条，反复出现的那些。**包含用户还在报的症状，以及上线了又被回滚的修复**，
  让下一次尝试从上次失败的地方开始。
- **Next move**：最有用的那**一个**下一步动作，要具体。

相邻的功能或工单不进简报，除非它挡着这条线。胶囊和线太长、一屏放不下时，**先砍细节，不砍线**。

## 边界

- **只读。** 不改代码、不提交、不推送。
- 写的时候过一遍 `/skill:unslop`。
- 会话里的发现引用文件名；共享记录里的发现引用它的来源（PR 号、工单 ID、错误条目）。
- 公开输出前先清掉私有信息。
- 本机没有的来源写成 `not available in this environment`，不要写成「查了没有」。
