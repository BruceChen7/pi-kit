# Structured diagram nodes

Visual Artifact supports three structured SVG diagram nodes in addition to the generic `mermaid` and `svg-diagram` nodes:

- `er-diagram` — entities, fields, and relationships.
- `architecture-diagram` — components, groups, boundaries, and connections.
- `layer-diagram` — ordered abstraction layers and optional cross-layer edges.

The nodes accept data, not coordinates or raw markup. Layout, orthogonal connectors, accessible SVG metadata, and stable IDs are generated by the pure modules under `diagram-core/`. The resulting SVG is displayed through the shared `SvgViewport`, so it supports fit, zoom, pan, fullscreen, source view, and copying the SVG markup to the clipboard.

## ER diagram

```json
{
  "type": "er-diagram",
  "props": {
    "entities": [
      {
        "id": "user",
        "name": "User",
        "fields": [{ "name": "id", "type": "int", "key": "PK" }]
      },
      {
        "id": "order",
        "name": "Order",
        "fields": [{ "name": "user_id", "type": "int", "key": "FK" }]
      }
    ],
    "relationships": [
      {
        "from": "user",
        "to": "order",
        "label": "places",
        "cardinality": "one-to-many"
      }
    ]
  }
}
```

## Architecture diagram

```json
{
  "type": "architecture-diagram",
  "props": {
    "nodes": [
      { "id": "web", "label": "Web app", "kind": "service" },
      { "id": "api", "label": "API", "kind": "service", "focal": true },
      { "id": "db", "label": "Postgres", "kind": "store" }
    ],
    "groups": [
      { "id": "runtime", "label": "Runtime", "members": ["api", "db"] }
    ],
    "edges": [
      { "from": "web", "to": "api", "label": "HTTPS" },
      { "from": "api", "to": "db", "label": "SQL" }
    ]
  }
}
```

## Layer diagram

```json
{
  "type": "layer-diagram",
  "props": {
    "layers": [
      { "id": "presentation", "label": "Presentation", "items": ["Web", "Mobile"] },
      { "id": "application", "label": "Application", "items": [{ "id": "api", "label": "API", "focal": true }] },
      { "id": "data", "label": "Data", "items": ["Postgres", "Redis"] }
    ],
    "edges": [{ "from": "Web", "to": "api", "label": "requests" }]
  }
}
```

## Choosing between nodes

- Use a structured node when the agent has entities/components/layers as data and the diagram should inherit Visual Artifact styling and validation.
- Use `mermaid` when an existing Mermaid source should remain authoritative, especially for ER diagrams already written as `erDiagram`.
- Use `svg-diagram` only for externally generated SVG that cannot be represented by the structured nodes. Its only supported prop is `svg`, containing the generated `<svg>…</svg>` markup. New artifacts must use this canonical field.
