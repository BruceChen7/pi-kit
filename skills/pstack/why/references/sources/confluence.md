# Confluence 长文档

本机没有这个源时（拿不到 `confluence_page`，或它取不到本空间的页）：**不要报「查无此项」**，
在 `Sources Consulted` 里写成 `not available in this environment`，并说清缺什么。

## 这个源里有什么

PRD、技术方案与 RFC、ADR、设计评审会议记录、领域背景页、事故复盘、runbook、优先级文档。

长文档是「为什么」在变成代码之前最常待的地方。一个不小的功能通常有一份文档。

## 怎么搜

**这个源只能父会话查。** `confluence_page` 是父会话的工具，调查者（子会话）拿不到。所以父会话
先查一轮，把命中页面的结论**当作代码锚点的一部分**发给调查者；`Sources Consulted` 里注明是
父会话查的。

起手：

```bash
# 有页面 ID 或 URL 时直接取
confluence_page({ pageId: "<id>" })
confluence_page({ url: "<url>" })
```

取回的内容里有 `markdown` 正文、`headings`、`links.urls`、`links.jiraKeys`。`jiraKeys` 直接
喂给工单那一源；`links.urls` 里指向别的 Confluence 页的链接可以顺着取。

检索词：

- 功能名、目标代码里的关键符号 / 类名
- 作者名（设计文档常在代码落地前先写）
- 错误字符串、用户可见的词
- 知道上线时间就按时段找

## 好证据长什么样

- 有「问题陈述」或「动机」小节的 PRD，且对得上目标代码的用途
- 「考虑过的替代方案」或「被否的做法」小节
- 复盘文档把目标代码记成某次事故的处置手段
- 会议记录写了「我们决定 X 因为 Y」，且作者与时间对得上 PR
- 一份 ADR 的 status / context / decision / consequences 填得实在，不是模板套话

## 常见坑

- **文档过期。** 方案常在实现前写、之后不更新。它可能描述了一个后来改掉的计划。对着实际改动核。
- **文档与现实漂移。** 文档说「我们会做 X」，代码实际做 Y。把分歧标出来，综合者摆它。
- **模板套话。** 有些流程要求填「Why」一栏，填的是废话。找具体的东西。
- **草稿与成稿并存。** 同一主题多份文档时，找最终版或最近更新的那份，看日期。
- **权限受限的页面。** 打不开就记成缺口，不要猜内容。

## 要返回什么

每份相关文档：

- 标题与 URL
- 作者与最后更新日期
- 动机原文（逐字引文）及其位置
- 相关链接页面（便于综合者引用）
- 是成稿还是草稿
