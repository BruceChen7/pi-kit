# Autonomous run

**你拥有退出条件。先定 done，再不停推到它。**

1. 第一次迭代前把退出条件写成一个可判定的谓词。测试全绿、复现修好、N 个 PR 全合、像素差为零。
2. 选唤醒机制。pi 没有 `/loop`，用 `scheduled-tasks` 的周期任务（`every: <duration>`），或自己按固定间隔重查。有明确事件可等时（CI、合并、ref 前进），用固定间隔做兜底心跳，间隔按「多久后结果值得重看」定。
3. 每轮只做证据支持的最小改动，对着谓词验证，推进了就提交，没推进就丢弃。「也许有用」的保险丝回滚，不要留着骑。
   按 `principles: sequence-verifiable-units` 每单元验证完再进下一个，不要攒到最后一起验。
4. 中途发现的问题归你。坏掉的 skill、相关 bug、不稳的验证器、评审噪音、工具故障、孤儿后续项、可修的漂移，自己处理掉。计划外的修复放自己的 PR。不要把可逆工作挂起来等人，也不要为此问人。只有不可逆动作、真正的产品或偏好选择、真正的死路才上报。谓词是主驱动，每次侧修之后回到它。
5. 每轮留一行决策轨（`/skill:show-me-your-work`），改了什么，谓词动没动。
6. 谓词满足就停。平台期不算停，继续换打法推过去。真死路要上报，不要空转，也绝不为了让步而放宽谓词。

**回复：** 退出条件，跑了几轮，什么落地了什么丢弃了，谓词最终状态。
